1. 작품 주제 및 요약

MuseAI는 스마트폰으로 촬영한 악보 이미지를 AI가 인식해 MusicXML로 변환하고, 웹 기반 인터랙티브 에디터에서 재생·교정할 수 있게 한 음악 학습 플랫폼이다. 종이 악보는 일방적인 시각 정보만 제공해 초보자의 진입 장벽이 높다는 점에서 출발했으며, 사용자는 악보를 실시간으로 재생하고 가상 피아노 건반과 연동된 시청각적 피드백을 받고, 마우스 클릭만으로 음표를 교정해 MIDI 파일로 추출할 수 있다.
구성 요소 역할
AI OMR 엔진 ONNX 딥러닝 모델을 통한 정밀 객체 검출
이론 교정 필터 music21을 이용한 비정상 음표 및 박자 자동 교정
인터랙티브 에디터 방향키와 툴바를 활용한 실시간 음표 편집
그랜드 피아노 렌더 사운드폰트 기반 실시간 다성 오디오 연주

2. 이론적 배경

OMR 모델은 CNN(Convolutional Neural Network) 기반으로 악보 내 객체를 검출한다. 이미지 $X$가 주어졌을 때 각 픽셀·바운딩 박스가 특정 악보 기호(음표, 쉼표, 빔 등) $Y$일 사후 확률을 최대화하며, 전체 확률은 개별 단위 확률의 곱으로 나타낸다.

$$ \hat{Y} = \arg\max_{Y} P(Y \mid X; \theta) $$ $$ P(Y \mid X; \theta) = \prod_{i=1}^{N} P(y_i \mid x_i; \theta) $$

인식된 기호는 music21 라이브러리로 음악 이론 규칙(마디 안 총 박자 수 일치)을 검증하며, 박자 오차가 생기면 비용 함수 $C$를 최소화하는 방향으로 길이를 보정한다.

$$ C = \alpha \sum_{j} |d_{\text{detected}, j} - d_{\text{corrected}, j}|^2 + \beta \left( \sum_{j} d_{\text{corrected}, j} - T_{\text{measure}} \right)^2 $$

($d$: 음표 길이, $T_{\text{measure}}$: 마디 기준 총 길이, $\alpha, \beta$: 각 항의 계수)

3. 실제 동작 화면

웹 인터페이스는 위쪽의 3단계 처리 카드와 아래쪽의 인터랙티브 악보 에디터로 나뉜다.

영역 화면 문구 역할
1. 이미지 전처리 기울기 보정, 그림자 제거로 OMR 최적화 업로드 영역(클릭·드래그)과 전처리 버튼
2. OMR 분석 AI가 악보 기호를 인식하고 MusicXML로 추출 "AI 악보 인식 시작" 버튼
3. 악보 최적화 노이즈 제거, 박자·옥타브 등 음악 이론 교정 "최적화 진행하기" 버튼
인터랙티브 에디터 악보 표시, 편집, 재생 "에디터 실행하기" 버튼과 편집·재생 도구
화면 상태 확인되는 내용

스크린샷 2 PDF 업로드 후 처리 완료 전처리·MusicXML 추출·최적화 완료 메시지, 조(E major)·박자(4/4)·14마디 표시
스크린샷 3 OMR 결과 렌더링 "Input_sheet.pdf" 제목과 대보표, 셋잇단음표 숫자 3 괄호 표시

4. 작품 상세 설명 (4단계 파이프라인)

단계 사용 기술 입력 $\rightarrow$ 출력
1. 악보 이미지 전처리 OpenCV 촬영한 악보 이미지 $\rightarrow$ 기울기·그림자가 보정된 이미지
2. OMR 기호 인식 oemer (CNN 딥러닝) 전처리된 이미지 $\rightarrow$ MusicXML
3. 음악 이론 기반 교정 music21 MusicXML $\rightarrow$ 정규화된 MusicXML
4. 인터랙티브 렌더링/연주 OSMD, Tone.js MusicXML $\rightarrow$ 웹 악보, 소리, 가상 피아노 건반

※ 교정 단계에서는 화음 그룹화 오류와 박자표 불일치를 자동 교정하고, 중복 인식 정제, 피아노 88건반 범위 조정, 마디 총 길이 보정을 수행한다.

5. 시스템 구현 상세

백엔드는 Python 기반 FastAPI 서버이며, 입력은 PNG·JPG·PDF(첫 페이지만 PyMuPDF로 2배 확대 변환)를 받는다. 이미지 바이트의 SHA-256 해시(file_hash)가 캐시 파일 이름의 기준이 된다.

5.1 이미지 전처리 (SheetMusicOptimizer, 목표 너비 1350px)

순서 처리 상세 알고리즘
1 기울기 보정 Otsu 반전 이진화 후 minAreaRect로 각도 계산, 15도 초과·0.15도 미만이면 회전 안 함
2 해상도 정규화 종횡비 유지, 너비 1350px, 높이·너비를 32의 배수로 패딩
3 대비 강화 (CLAHE) clipLimit 2.5, 타일 8×8 적응형 히스토그램 평활화
4 선명화 가우시안 블러 sigma 1.0, 강도 1.5로 오선·음표 머리 선명화
5 배경 정리 밝기 92번째 백분위수가 200 초과 시 해당 값 이상 픽셀을 흰색으로
6 최종 패딩·저장 32의 배수로 패딩 후 PNG(압축 레벨 4) 저장

5.2 OMR 실행 (oemer) 및 비동기 처리 모드

  • 비동기 작업: job_id를 발급하고 백그라운드 스레드에서 실행하며, OMR은 한 번에 1개만 실행(실행 중이면 429 오류).
  • 안전 실행: 입력 크기를 가장 긴 변 1024px 이하로 줄이고, 별도 프로세스에서 600초 제한으로 실행하며, 실패 시 데모로 대체하지 않고 오류를 그대로 알린다.
  • 메모리 절감: 연산 스레드 1개, ONNX Runtime CPU 고정, 이미지 95만 픽셀 상한, 추론 배치 크기 2.
모드 동작
빠름 (Fast) oemer 자체 기울기 보정 생략. 깔끔한 악보에 적합하며 기본값
정밀 (Deep CLAHE) oemer 기울기 보정 수행. 촬영·그림자·구김·기울어짐이 있는 악보에 적합

5.3 자동 교정 (ScoreCorrector) 5단계

순서 규칙 기준
1 음자리표 보정 없는 파트에 첫 파트는 높은음자리표, 그 외는 낮은음자리표 삽입
2 극소 파편 음표 제거 길이 0.125 quarter length (32분음표) 미만 음표·쉼표 제거
3 중복 음표 제거 같은 마디·위치·음높이 겹친 음표는 하나만 남김
4 88건반 범위 보정 MIDI 21(A0)~108(C8) 밖의 음을 옥타브 단위로 이동
5 마디 구조 정규화 music21의 makeMeasures·makeTies로 마디 길이와 이음줄 구조 정리

※ 교정 중 예외가 나면 원본 MusicXML을 그대로 유지한다. 렌더링 단계에서는 교정된 MusicXML로 MIDI 파일을 만들고 조표·박자표·마디 수·음표 수·파트 수를 분석해 표시한다.

6. 인터랙티브 에디터 및 재생 엔진

• 작업 방식: 상단 스위치가 켜져 있으면(기본값) 업로드 즉시 전처리 $\rightarrow$ OMR $\rightarrow$ 교정 $\rightarrow$ 렌더링이 연속 실행되고, 끄면 단계별 실행·디버깅이 가능. 업로드 없이 4마디 빈 대보표(4/4, C조)로 새 악보 작성도 가능.

수정 모드 켜야 편집 도구가 활성화되며 선택 음표의 마디·보표·음높이·박자 표시
피치 조절 반음·옥타브 올림/내림, 임시표, 음이름 직접 입력, 가상 건반 클릭
음길이·변환 온음표~16분음표, 쉼표 변환·삭제, Shift+건반으로 화음 쌓기

항목 내용

61건반 가상 피아노 C2~C7, 누르면 소리와 하이라이트, 재생 중 연주음에 맞춰 건반 하이라이트
오디오·음원 Web Audio API, Acoustic Grand Piano 사운드폰트(FluidR3_GM), 실패 시 내장 신디사이저
템포·볼륨·확대 40~200 BPM(기본 100), 볼륨 기본 85%, 확대·축소 50~200%
편의 기능 다크/라이트 테마, 사용 설명서(5개 탭), XML·MIDI 내려받기, 24시간 내 세션 복원, 캐시 정리

8. 배포 환경 및 운영 제약

Render.com 무료 웹 서비스(0.1 CPU, 512MB RAM)에 GitHub main 브랜치 푸시 시 자동 배포된다. render.yaml, build.sh, Dockerfile, requirements.txt, main.py로 구성되며, build.sh는 패키지 설치 후 CPU용 onnxruntime 1.17.3 재설치, oemer ONNX 체크포인트 사전 다운로드, omr_cache 폴더 생성을 수행한다.
제약 증상 대응
15분 무접속 시 절전 재접속 시 깨어나는 데 약 30~50초 소요 (정상 동작) 외부 모니터링으로 /healthz 주기 호출
RAM 512MB 4000px 이상 초고해상도를 정밀 모드로 인식하면 서버 재시작 가능 빠른 모드 사용, 입력 이미지 축소
임시 디스크 서버 재시작 시 캐시 초기화 가능 언제든 새 악보로 다시 편집 가능

대안 호스팅으로 Hugging Face Spaces(무료 16GB RAM, 2 vCPU), Railway.app, Fly.io를 소개하며, 로컬에서는 uvicorn main:app --port 8000으로 실행한다.

⚠️ 복잡한 악보의 클라우드 메모리(512MB) 초과 및 로컬 실행 권장:

Render 무료 플랜(512MB RAM)의 하드웨어 한계로 인해, 마디 수가 많거나(10마디 이상 대보표), 고해상도 다단 악보 등 객체 밀집도가 매우 높은 악보는 OMR 딥러닝 추론 중 Out of Memory 크래시가 발생할 수 있습니다. 따라서 복잡한 악보는 GitHub 소스코드 저장소를 로컬 PC로 클론하여 실행(git clone ... && uvicorn main:app --port 8000)하면 하드웨어 제약 없이 고속으로 분석할 수 있습니다.
